# brainstorm (짧은 버전)

superpowers의 brainstorming을 3시간에 맞게 줄였다. 원본은 키트의 `library/process/brainstorming`에 있다.
원본과 다른 점: 섹션마다 승인받지 않는다. 별도 설계 문서를 만들지 않는다. 끝나고 다른 스킬(writing-plans)로 넘어가지 않는다.

## 순서
1. 과제 원문, HUMAN.md, 이미 있는 docs/spec.md를 먼저 읽는다. 거기 답이 있는 건 묻지 않는다.
2. 질문은 한 번에 하나, 최대 5개. 질문마다 보기 2~4개와 추천 하나를 붙인다. "모름"이면 추천으로 정하고 '아직 모르는 것'에 적는다.
   묻는 순서(앞에서 정해지면 건너뛴다):
   - 누가, 어떤 순간에 쓰나
   - 시연에서 보여 줄 장면 하나(처음부터 끝까지 사용자가 하는 일)
   - MVP에서 뺄 것
   - 데이터는 어디서 오나(직접 입력, 공개 API, 더미)
   - 심사에서 차이를 만들 한 가지(결과는 '한 줄 목표'와 'MVP 기능'에 녹인다)
3. 3시간에 못 끝낼 크기면 줄이자고 먼저 말한다. 넣고 싶은 건 '나중 기능'으로 보낸다.
4. 접근이 둘 이상이면 2~3개를 장단점 한 줄씩과 추천으로 보여 준다.

## 결과
- spec 세션이면 `docs/spec-prompt.md`의 틀 그대로 마크다운 한 덩어리로 출력한다. 파일에 쓰지 않는다. 사람이 `docs/spec.md`로 저장한다(AI는 spec을 고치지 않는다).
- 구현 세션에서 애매한 곳을 정한 거면 DECISIONS.md에 "무엇을, 왜, 다른 선택지" 한 줄로 적는다.
