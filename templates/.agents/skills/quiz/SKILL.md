# quiz

## 문제 만들기
1. `git diff <이전 작업 끝 커밋>..HEAD --stat`으로 바뀐 파일을 보고, 핵심 파일은 `git diff <커밋>..HEAD -- <파일>`로 실제 바뀐 줄을 읽는다. DECISIONS.md의 새 줄도 본다. 문제는 여기서만 낸다. QUIZ.md에 지난번 틀린 개념이 있으면 이번 코드와 이어지는 것 하나를 다시 물어도 된다.
2. 5문항을 먼저 다 정해 두고 하나씩 낸다. 섞어서:
   - 이해 문항 2개 이상: "왜 이 방식으로 짰나", "이 코드가 깨지면 어디서 보이나", "이 값을 바꾸면 무엇이 달라지나"
   - 위치 문항: "X는 어느 파일·함수가 맡나"
   - 흐름 문항: "사용자가 Y를 누르면 어떤 순서로 도나"
3. 보기 4개, 정답 하나. 오답은 그럴듯하게(실제 있는 다른 파일·함수 이름, 흔한 오해). 정답 위치가 한쪽으로 몰리지 않게 섞는다.
4. 정답이 코드에서 확인되지 않거나 모호하면 그 문제는 버리고 다른 걸 낸다.

## 내기
- 한 번에 한 문제. 형식:
  ```
  Q3/5. <질문>
  A) ...  B) ...  C) ...  D) ...
  ```
- 사람이 답하기 전에 정답이나 힌트를 말하지 않는다.
- 답하면 맞았는지, 정답, 해설 한 줄(근거 파일:줄)을 말하고 다음 문제로 간다.

## 끝나면
- 점수를 한 줄로 말한다.
- 틀린 문제만 `QUIZ.md`에 덧붙인다: 작업 번호, 문제, 사람의 답, 정답, 해설.
- 이어서 NOTES.md를 쓰라고 사람에게 안내한다. AI가 대신 쓰지 않는다. 사람이 다 쓰면 NOTES.md, QUIZ.md, DECISIONS.md를 `docs: <번호>번 메모·퀴즈`로 커밋한다.
