# plain-writing

AI가 쓴 한국어 글에서 **AI 티를 줄여 사람이 쓴 글처럼 읽히게** 한다. 사람이 쓴 글처럼 읽히면 처음 보는 사람도 한 번에 이해한다. 이 레포의 AI 커밋에서는 "정본", "실측", "가드" 같은 어려운 말이 사람 커밋보다 100~300배 많았다. 어려운 말을 빼는 일과 AI 티를 빼는 일은 상당 부분 같다.

워터마크는 이 스킬과 상관없다. 단어 몇 개를 바꿔도 워터마크는 남는다. 이 스킬은 읽히는 글을 만드는 데만 쓴다.

## 0. 순서

글 종류를 묻지 않는다. 어떤 글이든 같은 순서로 한다.

1. **원문에서 지킬 것을 먼저 뽑는다.** 숫자, 날짜, 이슈 번호, PR 번호, 커밋 해시, 파일명, 함수명, 사람 이름, 링크, 화면에 뜨는 글자, 인용문, 코드. 이 목록은 4장 검사에서 대조한다.
2. **1장(AI 티 빼기)과 2장(쉬운 말)을 적용한다.** 3장(사실 보존)은 늘 지킨다.
3. **4장 검사를 돌린다.** 걸린 것이 0개가 될 때까지 고치고 다시 돌린다.
4. 결과 글을 보여 준다. 그 아래 "고친 곳" 3~6줄과 검사 결과 한 줄을 붙인다.

## 1. AI 티 빼기

### 금지 단어 표

| 묶음 | 단어 |
|---|---|
| 어디서나 나오는 AI 말버릇 | 얹다, 갈래, 짚다, 핵심, 흐름, 장치, 차원, 축, 지점, 맥락 |
| AI식 개발 은어 | 정본, 실측, 무변경, 단언, 판정, 불변, 무관, 가드, 게이트 |

- 금지 단어가 나오면 **단어만 갈아 끼우지 않는다.** 그 문장이 무슨 말을 하려는지 다시 보고 문장째 새로 쓴다. 대부분은 그 단어를 빼고 내용을 바로 말하면 된다.
  - 예: "규칙은 세 갈래로 나뉜다: 쉬운 말, AI 말투, 사실 보존" → "규칙은 쉬운 말, AI 말투 빼기, 사실 보존이다."
  - 예: "이 지점에서 막혔다" → "로그인 버튼을 누른 뒤 화면이 멈췄다."
  - 예: "인터뷰 문항 자동답변 금지 가드 (서빙 정본)" → "인터뷰 질문에 AI가 대신 답하지 못하게 한다"
- 바꿀 말은 일부러 정해 두지 않는다. 정해 두면 그 말이 새 버릇이 된다.
- 단어를 **예로 들어 언급**하는 문장(따옴표 안)은 고치지 않는다.
- 회귀, 멱등, 폴백은 금지하지 않는다. 처음 나올 때 2장 P1대로 풀어 쓴다.
- 이 표는 2022년 이전 한국어 커밋·PR 8,979개(사람)와 2026년 AI가 쓴 사내 저장소 커밋·PR 3,126개(AI)의 단어 빈도를 비교해 뽑았다(2026-10-14). 커밋·PR 기준이라 블로그·SNS에만 나오는 AI 단어는 아직 없다.
- 표는 늘리지 않는다. 넣고 싶은 단어가 생기면 같은 방식으로 다시 세서 사람 쪽보다 3배 이상 많을 때만 넣는다. 그때 하나를 뺄지도 같이 정한다.

### AI 말투

- **A1** 연결어미(-고, -며, -지만, -아서, -어서) 바로 뒤에 쉼표를 찍지 않는다. 쉼표로 길게 이어진 문장은 둘로 나눈다. (AI가 사람보다 약 4.8배 많이 쓴다.)
- **A2** "A가 아니라 B" 같은 대조 틀이 한 글에 두 번 이상 나오면 바꿔 쓴다. 한 번은 둔다. 바꿀 때는 B만 바로 말하거나 문장을 둘로 나눈다. (AI가 사람보다 약 9.2배 많이 쓴다.)
- **A3** 낫표 「」 대신 따옴표를 쓴다. 화면에 뜨는 글자는 따옴표로 감싼다.
- **A4** 번역투를 고친다: "~되어진다" → "~된다", "~에 의해 만들어진" → 한 사람을 주어로, "~에서의" → 풀어 쓴다. ("~을 통해", "~것이다", "활용", "해당"은 사람이 더 많이 쓰므로 고치지 않는다.)
- **A5** 멋진 한 줄로 끝내지 않는다. 할 말을 다 했으면 거기서 끝낸다.
- **A6** 목록을 억지로 세 개에 맞추지 않는다. 굵은 글씨는 한 문단에 하나까지.

## 2. 쉬운 말 (AI가 만든 어려운 말 풀기)

- **P1** 전문 용어는 쉬운 말을 먼저 쓰고 원래 용어는 괄호에 둔다. 괄호는 처음 한 번만.
  - 예: "화면 없이 따로 시험할 수 있는 계산 코드(순수 함수)"
  - 뜻을 확실히 모르는 용어는 풀지 않고 원문 그대로 둔다. 짐작으로 푼 설명은 사실을 바꿀 수 있다.
- **P2** 팀 안에서만 통하는 이름(A안, B안, 목업 이름, 내부 별칭)은 처음 한 번 무엇인지 풀어 쓴다.
  - 예: "B안" → "B안(웹 두 열 화면)"
- **P3** 붙인다, 물린다, 뗀다, 접는다, 박는다처럼 화면을 물건처럼 다루는 동사 대신 사용자가 보는 결과를 쓴다.
  - 예: "끝냄·지금 차례를 붙인다" → "끝낸 미션과 지금 할 미션이 보인다"
- **P4** 명사만 이어 붙이지 않는다. 문장으로 쓴다.
  - 예: "줄 판정 순수 함수 + 테스트" → "미션 줄 상태를 정하는 코드와 그 테스트를 추가했다"
- **P5** 이유는 읽는 사람이 겪는 장면으로 말한다. 코드 위치(행 번호, 함수명)는 필요할 때만 뒤에 붙인다.
- **P6** 줄여 써도 누가, 무엇 대신 무엇을, 왜는 남긴다.
- **P7** 비유가 사실을 바꾸면 비유를 빼고 그냥 설명한다.

## 3. 사실 보존 (늘 지킨다)

- **F1** 0단계 1번에서 뽑은 것(숫자, 이름, 번호, 링크, 화면 글자, 인용)은 한 글자도 바꾸지 않는다. 한국어 글은 한국어로 바로 쓴다. 영어로 썼다가 번역하지 않는다. 번역을 거치면 화면 글자와 이름이 바뀐다.
- **F2** 추측을 단정으로, "해야 한다"를 사실로 바꾸지 않는다. 원문에 없던 이유, 사례, 비유, 숫자, 전망을 넣지 않는다. 원문에 없는 칸(예: PR의 "어떻게 확인했나")은 지어내지 않는다. 비워 두거나 빼고 빠졌다고 알린다.
- **F3** 한 글 안에서 어미를 섞지 않는다. 문체(~한다, ~해요, ~합니다)는 원문을 따른다.
- **F4** 글의 순서, 제목, 목록 모양은 원문을 따른다. 하나만 예외다: 설명 문장 사이에 파일명, 함수명, 명령어, 설정값이 끼어 문장을 끊으면 그 부분을 글 끝 "세부"로 옮긴다. 지우지 않는다.


## 4. 검사 (눈 말고 검색으로)

같은 모델이 쓴 글을 같은 모델이 다시 읽으면 자기 버릇을 못 본다. 그래서 결과 글을 파일로 저장한 뒤 아래 명령으로 센다.

```bash
f=결과파일.md
echo "금지 단어:"; grep -noE '얹|갈래|짚|핵심|흐름|장치|차원|축|지점|맥락|정본|실측|무변경|단언|판정|불변|무관|가드|게이트' "$f"
echo "연결어미 뒤 쉼표:"; grep -noE '[가-힣](고|며|지만|아서|어서), ' "$f"
echo "낫표:"; grep -c '「' "$f"
echo "대조 틀:"; grep -o '아니라' "$f" | wc -l
```

- 링크 글자([...] 안), 인용문, 코드(백틱 안), 다른 문서의 제목은 검사 대상이 아니다. 여기서 걸린 것은 3장 F1대로 그대로 둔다.
- 금지 단어가 걸리면 그 줄이 단어를 **언급**한 것인지 **쓴** 것인지 본다. 쓴 것이면 1장대로 문장째 다시 쓴다. ("축"은 압축, 구축 같은 단어에도 걸린다. 그런 경우는 그대로 둔다.)
- 연결어미 뒤 쉼표와 낫표는 0개가 될 때까지 고친다. 대조 틀은 2개 이상이면 고친다.
- 마지막으로 0단계 1번 목록을 결과 글에서 하나씩 찾는다. 빠지거나 바뀐 것이 있으면 되돌린다.
- 결과에 한 줄로 적는다. 예: "검사: 금지 단어 0 · 쉼표 0 · 낫표 0 · 대조 1 · 지킬 것 12개 중 빠진 것 0"
